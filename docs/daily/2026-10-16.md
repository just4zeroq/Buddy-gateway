## 涉及功能

### A. 动态通道注册：所有权与生命周期收尾（`57c43e2`、`fc9c60a`）

- 注册必须携带**非空 `plugin_id`**：重复注册保持首次结果，注销只有登记时的
  所有者才能执行，避免互相覆盖/误删别人的通道绑定。
- 生命周期对称：注册 → 解析 → 注销，`build_channel` 读运行时注册表。

### B. Telegram 入站图片格式（`534f59e`、`5c93229`）

- Bot API 的 `PhotoSize` 不带 `mime_type`，而 Bot API 照片实际是 JPEG；此前会被
  当成默认类型落盘成 `.png`，导致扩展名与真实编码不符。现在**固定为
  `image/jpeg`**。
- 更一般地：下载器识别出的真实图片 MIME 会**在决定存储 key / 扩展名之前**生效
  ——即一个以 `.png` 结尾的 URL 实际返回 JPEG 时，落盘为 JPEG。

### C. Telegram 准入缓存与相册重试（`89017b1`）

- update 与 message 两个去重窗口**彼此独立**且各有上界（各 1000），update 的
  高频 churn 不会再挤掉编辑消息要匹配的源 message id。
- 相册任务槽在**激活之后**才占用；被动成员数量有上限。
- 显式 429 重试能恢复嵌套上传句柄；无法恢复的重试直接拒绝。
- 会排队 Agent 工作的短回调保持 `/stop` 可响应（不被长任务卡死）。

### D. QQ 私聊流式前缀（`453b706`）

工具调用前**已经发出或正在发送**的正文被冻结为固定前缀，后续回答片段在其上
延伸；此前每次流式更新都会重复追加这段叙述文字。

### E. `ERROR` 作为失败终态（`13f61f5`、`5a94dc7`、`d7e9347`、`3d573d0`）

这是本轮最有行为影响的一组修复：

- `ERROR` 事件成为**终结事件**：flush 已产生的增量、投递错误、结束本回合，
  **不再等待后续完成事件**。此前完成事件会把失败回合误标为成功。
- 各通道显式关闭处理器执行清理，清理**超过 5 秒**取消并记录诊断
  （`close_event_stream` 有界）。
- 会失败的回合最终状态为 failed；小艺通道同步发送 A2A `failed` 状态并保留错误
  展示。
- processor 的建立保持在通道清理边界**之内**；Telegram 预览流停止时同时关闭
  宿主 processor，避免错误回合跳过清理。
